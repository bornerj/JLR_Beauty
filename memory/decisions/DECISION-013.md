Date: 2026-08-12
Context: O usuário trouxe um brainstorm feito com apoio de IA (`retrofit/ADMIN-V2-RETROFIT-OVERVIEW.md`, `retrofit/Retrofit_Concepts.docx`, `retrofit/RETROFIT-000.md` a `RETROFIT-014.md`) propondo um retrofit profundo do painel administrativo: substituir a navegação por módulos (menu com Agenda/Vendas/Metas/Performance/Produtos/... crescendo por adição, o mesmo padrão que o PLAN-0021 já reconheceu ter atingido o limite) por uma experiência orientada a Panorama → Rede → Diagnóstico → Ação, inspirada em drill-down/roll-up de Data Warehouse, com Health Score, board operacional de pedidos, mapa de capacidade de agenda, portfólio vivo de produtos, radar executivo etc. Antes de planejar, foi feito RAG no schema Prisma, middleware de auth/unit-scope, módulo `admin/kpis`, roteamento do frontend (`apps/web/src/app/App.tsx`) e models de domínio (Order, Appointment, Service, Subscription, FranchiseLead) para validar se a infraestrutura que a proposta assume realmente existe. Confirmou-se que sim: `Order` já tem `fulfillmentStatus` + timestamps de separação/embalagem/despacho/entrega, `StockMovement`/`StockReservation` (PLAN-0020) cobrem o ledger, `resolveUnitScope`/`canAccessUnit` (PLAN-0020) cobrem o escopo por unidade fail-closed, e `admin/kpis` já calcula receita/margem/comissão. A avaliação de viabilidade completa, incluindo riscos, está registrada em `memory/plans/PLAN-0022-ADMIN-V2-FUNDACAO-OPERACAO.md`. Um gate socrático (RULES.md §15) foi aplicado antes de planejar; as respostas do usuário estão citadas na Decision abaixo.
Decision: Construir o "Admin V2" como uma camada nova e paralela ao Admin atual, nunca como reescrita. Regras fixadas:
1. Rotas: `/admin` (legado) e `/admin-v2` (novo) coexistem; nenhuma funcionalidade do legado é removida como pré-condição para o V2 nascer.
2. Sequenciamento: o desenvolvimento do Admin V2 corre em paralelo aos planos ainda abertos (PLAN-0019 bloqueado por TLS, PLAN-0020 e PLAN-0021 pendentes de commit/push), sem esperá-los fechar — decisão explícita do usuário no gate socrático. Único acoplamento mantido: o Admin V2 não pode ser declarado pronto para uso externo/produção enquanto o PLAN-0019 (TLS/HTTPS) permanecer bloqueado, porque o Admin V2 concentra ainda mais dados sensíveis de rede/margem por unidade do que o legado.
3. Aposentadoria do Admin legado: **não decidida agora** (resposta explícita do usuário) — os dois admins convivem indefinidamente até nova decisão; cada onda do V2 não implica remoção automática da tela legada equivalente.
4. Arquitetura: todo cálculo de negócio (margem, Health Score, estados operacionais derivados, escopo de unidade) mora no backend, numa camada nova `apps/api/src/modules/intelligence/`, nunca no frontend. O frontend do V2 mora em `apps/web/src/admin-v2/`, isolado do shell legado (`apps/web/src/components/pages/AdminContent.tsx` e módulos `admin-*`), que continuam intocados.
5. Reuso: cadastros (produtos, serviços, planos, pessoas, cupons, entrega) e telas de Sistema (branding, textos, seções, integrações, segurança, infra) **não são reescritos estéticamente** nesta fase — o V2 os acessa via adapter/link para as telas legadas existentes até haver valor real comprovado em uma versão nativa.
6. Identidade visual: os tokens de marca atuais (`primary #00967f`, `gold #c5a059`, `forest`, `cream-sidebar`, `champagne`) são preservados como base do shell do Admin V2; cores novas só são introduzidas como tokens semânticos de estado (saudável reaproveita o teal da marca; atenção=âmbar, crítico=vermelho, informação/previsão=azul), nunca substituindo a paleta existente.
7. Health Score v1: fórmula fixa e determinística (Rentabilidade 30% / Crescimento 20% / Ocupação 20% / Recorrência 15% / Estoque 10% / Assinaturas 5%), sem pesos configuráveis nesta fase — decisão explícita do usuário no gate socrático.
Consequences: Toda a Fundação e a Experiência Operacional (Ondas 0-9 do `PLAN-0022`) herdam estas 7 regras sem precisar revalidá-las onda a onda. Qualquer proposta futura de aposentar uma tela do legado, mudar a paleta do V2, tornar os pesos do Health Score configuráveis, ou acoplar o cronograma do V2 a outro plano em aberto deve primeiro atualizar esta decisão (não decidir isoladamente dentro de uma onda). Se o PLAN-0019 (TLS) seguir bloqueado quando a Fundação+Operação estiver pronta, o Admin V2 pode continuar em uso interno (localhost/rede interna), mas não deve ser anunciado como superfície de produção externa até TLS ser resolvido.
