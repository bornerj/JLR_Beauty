Status: ACTIVE
Date: 2026-07-05
Context: PLAN-0018 Onda 3 (SEC-27) — a auditoria de segurança apontou que o CORS da API aceita requisições sem header `Origin`, o que em tese permitiria a um atacante não-browser (script, curl, ferramenta de exploit) contornar a validação de origem. Uma restrição foi implementada bloqueando requisições sem `Origin` em produção (com exceção explícita para webhooks Stripe/Z-API e health checks, que são chamadas servidor-a-servidor legítimas). Antes de considerar o fix concluído, foi feito um teste com um browser real (Chrome headless, não apenas `curl`): uma página servida pela mesma origem do nginx fazendo `fetch('/api/public/products')` recebeu `403` — o próprio Chrome não envia `Origin` num fetch GET same-origin, e como este projeto serve web e api na MESMA origem via nginx (não são domínios/portas públicas separadas), a restrição bloquearia o tráfego legítimo do próprio frontend em produção, não apenas atacantes. Ver ERR-0042 em DEBUG-HISTORY.md para o relato técnico do bug encontrado durante essa tentativa.
Decision: Não implementar a exigência de `Origin` obrigatório nesta arquitetura. Reverter para o comportamento original (`!origin => allow`, já existente antes desta auditoria). SEC-27 permanece cientificamente identificado como um item de auditoria sem correção viável enquanto web e api forem servidos pela mesma origem via nginx reverse proxy. Não perseguir esse fix novamente sem antes separar os domínios de web/api (mudança de infraestrutura fora do escopo de segurança pontual) — e, mesmo que a separação de domínios ocorra no futuro por outro motivo, qualquer tentativa de reintroduzir a exigência de `Origin` deve ser revalidada com um browser real (Chrome/Firefox headless fazendo o fetch de fato), não apenas com `curl`, pois `curl` não reproduz fielmente o comportamento de envio de headers do browser.
Consequences: A proteção real contra o cenário de ataque que motivou o PLAN-0018 (credencial roubada via MITM + chamada direta ao backend) continua sendo a camada de autenticação (`requireAuth`/`requireAdmin`, reforçada nas Ondas 1-2) e a expiração curta do access token (SEC-25, 15min) — não o CORS, que é um mecanismo de proteção do browser contra sites maliciosos e não impede um atacante não-browser de forjar ou omitir o header `Origin` livremente. Se no futuro alguém questionar por que `/api/*` aceita requisições sem `Origin` mesmo em produção, a resposta é: isso é necessário (não um descuido) — remover quebraria o próprio frontend. Qualquer revisão de segurança futura que reencontrar esse "gap" deve consultar este registro antes de tentar corrigi-lo novamente.
